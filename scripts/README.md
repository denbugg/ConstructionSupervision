# scripts — служебные скрипты

Всё, что вызывается из `Makefile`. Скрипт делает одно понятное действие и печатает, что он сделал.

**Скрипты пишутся на Python, а не на bash.** Демо-стенд работает на Windows, где bash нет, а
`make` исполняет рецепты через cmd. Поэтому `Makefile` лишь вызывает `python scripts/<имя>.py`,
а на Windows тот же скрипт запускается напрямую ([docs/runbook.md](../docs/runbook.md), раздел 3).

| Скрипт | Что делает |
| :--- | :--- |
| `_common.py` | Общее: корень репозитория, чтение `.env` (окружение процесса главнее файла), заглушка «не реализовано» |
| `openapi_dump.py` | Снимает OpenAPI сервиса импортом приложения, без докера и БД; используется в CI |
| `fetch_models.py` | Скачивает веса в `data/models/`: `yolov8s-worldv2.pt` и `openclip-vit-b32/open_clip_model.safetensors`; сверяет sha256, повторно не качает. `--force` — скачать заново |
| `health.py` | Опрашивает `/health/ready` сервисов и `/health` gateway (порт из `GATEWAY_PORT`), печатает сводку; код 1, если кто-то не готов |
| `seed_images.py` | Собирает демо-хронологию снимков `data/seed/images/<камера>/ГГГГММДД_ЧЧММСС.jpg` из датасета Лимы по `data/seed/chronology.json`; `--yes` удаляет папки камер не из хронологии |
| `seed.py` | Демо-данные: объект из `data/seed/object.json` (находится по имени) → график из `data/seed/schedule.xlsx`, если его ещё нет (`--force-plan` заменяет) → правила этапов без шаблона из `data/seed/rules.json`, если у этапа правила ещё нет (правка в интерфейсе не затирается) → снимки → камеры и зоны из `data/seed/cameras.json` → ожидание распознавания → если разметка изменилась, ожидание пересчёта фактов окон по ней (`updated_at` окон не раньше импорта зон) → `POST /analysis/runs?wait=true` → сводка отклонений. Снимки грузятся раньше зон, чтобы эталонным кадром камеры стал её первый снимок |
| `demo.py` | Готовит демо-объект, как `seed.py`, и ведёт по сценарию `data/seed/expected.json` с паузами: для каждого дня — что показать, найденные отклонения со ссылкой на снимок-доказательство на экране камер и пометка, если лента разошлась со сценарием. Шаг «правка правила» меняет правило через API и возвращает его (спрашивает разрешения; `--rule-edit` — без вопроса). `--no-pause` — без пауз |
| `e2e.py` | Сквозной сценарий на поднятом стеке, на отдельном объекте «E2E: …» из тех же `data/seed` (график каждый раз заново). Проверяет: лента совпадает с `data/seed/expected.json` по дням, ничего лишнего; у отклонений, кроме D10, есть факты и снимки; правка правила убирает D2 и оставляет D1, откат возвращает сценарий. Код 0 — пройден |
| `_scenario.py` | Общее для `demo.py` и `e2e.py`: чтение `expected.json`, сверка ленты со сценарием, правка правила этапа |
| `contracts.py` | Снапшоты OpenAPI всех сервисов (`packages/contracts/openapi/`) и TS-типы (`packages/ts-api-client/src/`). Снапшот снимается `openapi_dump.py` в одноразовом контейнере из образа сервиса, с кодом рабочей копии и настройками по умолчанию, как в CI. Нужны собранные образы (`docker compose build`) и Node.js с npm; повторный запуск без правок ничего не меняет |
| `test.py` | Тесты сервисов (`test.py plan site` или все) в одноразовых контейнерах из их образов: код сервиса и `packages/contracts` — из рабочей копии, pytest ставится в контейнер, база — `<база>_test` рядом с рабочей (заводится, если её нет). Замена `make test` на Windows, где pytest сервиса на хосте не запустить. Нужен поднятый `postgres` стека |
| `backup.py` | Заготовка, не реализован: дамп трёх баз и зеркало бакетов S3 (ручная замена — runbook, раздел 8) |
| `labelme_to_zones.py` | Переводит разметку LabelMe (метка `ТИП:Название`) в `data/seed/cameras.json` с нормированными координатами |
| `export_zones.py` | Обратный путь: зоны демо-объекта, размеченные в редакторе интерфейса, из site-service в `data/seed/cameras.json` — чтобы `seed.py` воспроизвёл разметку на чистом стеке |

Какие скрипты уже написаны, а какие ещё нет, видно по задачам в [docs/board.md](../docs/board.md).
Ещё не написанный скрипт — заготовка: печатает номер задачи и возвращает код 1.

Отдельных скриптов `bootstrap` и `reset` нет и не будет. `.env` создаётся из `.env.example`
вручную или целью `make`, базы и роли — скриптом инициализации Postgres (`infra/postgres/init/`),
а сброс — это `docker compose down -v`.

## Правила

- Скрипты идемпотентны: повторный запуск не ломает состояние.
- Никакой бизнес-логики: скрипт вызывает API сервисов, а не лезет в их базы напрямую.
  Исключение — `backup.py`, который работает с инфраструктурой.
- Все адреса и ключи берутся из `.env`, ничего не зашито.
- Скрипт, который что-то удаляет, спрашивает подтверждение либо требует флаг `--yes`.
- Зависимости скриптов — только стандартная библиотека и `httpx`: никакой установки
  «ради одного скрипта».
