## 2. Что режем первым, если не успеваем

По порядку — сверху вниз:

1. **Генератор графика по МРР** — демо начинается с импорта графика из XLSX, как в ТЗ, п. 7.
2. **Перетаскивание в Ганте** — даты правятся формой.
3. **Экран загрузки снимков** — загрузка скриптом `seed.py` и через Swagger.
4. **LLM-резюме** — только шаблонное резюме (`LLM_ENABLED=false`).
5. **PDF-отчёт** — резюме и таблица отклонений в интерфейсе.
6. **D5, D6, D7** — после остальных отклонений.
7. **GPU** — работа на CPU с честно указанной скоростью.

**Не режем никогда:**
- лента отклонений с карточкой: текст, числа, правило, снимок с рамками;
- редактор правил «этап → техника»: на нём держится демонстрация архитектурного критерия;
- статус объекта и прогноз;
- D2, D3, D4, D10 на демо-данных.

## 3. Риски и реакция

| Риск | Вероятность | Реакция |
| :--- | :--- | :--- |
| Нет серии снимков с неподвижных камер для демо | Высокая | Задача человека H1 в первый же день. Запасной путь — меньше камер и дней, но с одной точки съёмки |
| Самосвалы и миксеры не попадают в снимки раз в 30 минут | Высокая | Транзитное окно в методике (раздел 5); тест «нормальный день» не даёт ложного D2 |
| Не хватает размеченных данных по башенным кранам и бетононасосам | Высокая | Zero-shot детектор с текстовыми промптами работает без разметки; класс с низким качеством честно помечается в метриках |
| Нормы МРР последней редакции не оцифрованы | Средняя | Генератор режется первым; график импортируется из XLSX |
| LLM недоступна из-за сети или блокировок | Средняя | Провайдера проверяет человек с демо-машины (H4); `LLM_ENABLED=false` переводит резюме на шаблон |
| Docker не видит GPU на Windows | Средняя | Проверка в задаче H6 в первый день; запасной путь — `VISION_DEVICE=cpu` |
| `make` не работает на Windows | Точно | Все скрипты на Python, команды для PowerShell — в [runbook.md](runbook.md), раздел 3 |
| Интеграция «в последний день» | Высокая | Рубеж R2 — 26.09, а не 28.09 |
| Демо ломается на чужой машине | Средняя | 28.09 полный прогон с нуля: `docker compose down -v` → `pull` → `up` → `seed.py` → `e2e.py`, плюс записанное видео как страховка |

## 4. Что не делаем, даже если останется время

Соблазны, которые убивают хакатонные проекты. Зафиксировано, чтобы не спорить в процессе:

- трекинг конкретных машин, видеопоток, распознавание номеров;
- детекция подвоза материалов и внутренних работ;
- ПОС: подбор машин по КСР, 299-ПП, окна тишины;
- собственная система пользователей и ролей;
- Kubernetes, брокер сообщений, мультиарендность;
- переписывание уже работающего сервиса «красивее».

Свободное время идёт в качество объяснений, демо-данные, метрики, документацию и репетицию
питча. Это ровно те критерии, по которым нас оценивают.
