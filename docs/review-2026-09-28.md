## 1. Резюме

1. **`main` красный по линту.** Коммит `133f6ab` («веха» → «этап») удлинил три докстринга до
   101 символа и разложил параметризацию в `test_cpm.py` в одну строку. `ruff check` — 3 ошибки,
   `ruff format --check` — 1 файл. CI на этом же коммите красный, и это первое, что увидит эксперт
   в репозитории. Чинится за пять минут (раздел 4, A1). Unit-тесты при этом зелёные: 543 теста
   в трёх сервисах.
2. **Стек с нуля у эксперта не воспроизводится без ручных шагов, которых нет в раздаче.**
   Дообученные веса (`ulima-v3`, `ce-ulima-v1`) лежат только на стенде, `fetch_models.py` их не
   знает; демо-кадры — 56 файлов из датасета Лимы (CC BY 4.0), в git их нет; реестр ghcr
   приватный; репозиторий приватный. Техническая экспертиза 30.09–14.10 — это как раз «поднять
   по runbook на чужой машине». Без весов vision работает на zero-shot, который технику Лимы не
   видит (mAP50 0,07), и демо-сценарий не сойдётся. Решение — один ассет релиза с весами
   и кадрами и его скачивание скриптом (A2), плюс публичные пакеты и репозиторий (человек).
3. **Не принято решение, на каких весах показывать.** Runbook §2 говорит: сценарий проходит на
   `ulima-v3`; в `.env` стенда после репетиции стоит `ce-ulima-v1`, с которым в «нормальный день»
   появляется лишнее D4 крана вне участков. Решение — человека, сегодня. Рекомендация: демо на
   `ulima-v3`, а в метриках честно обе строки (`ce-ulima-v1` лучше на снимках организаторов).
4. **Артефактов сдачи в репозитории нет:** презентация по шаблону (слайды 7–11 обязательны),
   документация `.docx/.pdf`, видео демо (ТЗ, раздел 9). Это основной объём работы 28–29.09.
   Агент может собрать содержание слайдов и документацию (A4, A5); шаблон, перенос в дизайн
   и запись видео — человек.

## 6. Проверки: агент и тестер

Принцип разделения: агент проверяет всё, у чего есть машинно-проверяемый критерий (код возврата,
совпадение с `expected.json`, наличие файла, число в ответе). Тестер проверяет то, что видит
глазами и делает руками: рамки на правильных машинах, читаемость PDF, тексты, диалоги браузера,
GPU на Windows, тайминг перед живой аудиторией — и делает это **как эксперт, который видит
проект впервые**.

### 6.1. Проверяет агент (сессия на стенде с Docker)

В этом порядке, каждый шаг — до зелёного, иначе стоп и запись в board §9:

1. `ruff check` и `ruff format --check` — после A1 чисто.
2. `scripts/test.py` без аргументов — все сервисы, включая api-тесты с базой `<база>_test`.
3. `apps/web`: `npm ci && npm run build` — без ошибок типов.
4. `scripts/contracts.py` → `git diff --exit-code packages/contracts/openapi` — снапшоты OpenAPI совпадают с кодом (CI это проверяет; после T45–T48 легко разойтись).
5. `docker compose config` без предупреждений при заполненном `.env`.
6. Полный цикл с нуля, как эксперт: `docker compose down -v` → `pull` (или `up --build`) → `up` → `health.py` 5/5 → `fetch_models.py --demo` (A2) → `seed.py` → `e2e.py` зелёный. Записать время каждого шага в runbook §10.
7. `GET /api/v1/vision/model` → `device: cuda`, `weights` — файл по решению Б5.
8. `POST /api/v1/analysis/reports` дважды за один период → в `GET …/reports` два файла (T48); PDF скачивается, размер > 0, в нём есть раздел резюме.
9. `LLM_ENABLED=false` → отчёт формируется с шаблонным резюме; вернуть `true` → резюме от модели проходит проверку фактов (5 из 5 на демо-объекте, T35).
10. Правка правила через API (`rule_edit` в `e2e.py`) — D2 исчезает и возвращается.
11. Негативные через API: снимок без времени → `NEEDS_TIME`; повторная загрузка того же файла → `rejected` по sha256; запрос без `X-API-Key` → 401 с конвертом ошибки; `X-Request-Id` возвращается и виден в логах всех сервисов по цепочке.
12. `preflight.py` (A6) на исправном и на намеренно испорченном `.env`.
13. Документы: `grep` на «веха», «MinIO» (вне ADR-0016 и раздела перехода), «23.09» в roadmap; ссылки в README ведут на существующие файлы.

Что агент **не может** подтвердить и не должен писать как «проверено»: правильность рамок на
кадре, читаемость PDF, качество текста резюме, поведение диалога выбора папки в браузере,
реальную скорость на GPU стенда (только через `vision/model` и логи), впечатление эксперта.
