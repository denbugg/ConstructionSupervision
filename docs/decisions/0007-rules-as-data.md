# ADR-0007. Правила и пороги — данные, а не код

**Статус:** принято, 17.09.2026. Строка про классы техники отменена
[ADR-0014](0014-equipment-classes-file.md), места хранения текстов и нормативов уточнены
в [ADR-0011](0011-generator-and-reports-as-modules.md).

## Контекст

ТЗ содержит прямой критерий оценки: «архитектура позволяет добавлять новые типы техники,
камер и планов без переделки кода». Заказчик подчёркивал, что нормативов по количеству
машин он не даёт и правила задаёт эксплуатирующая сторона, редактируя их в интерфейсе.

## Решение

В коде не существует ни одного захардкоженного класса техники, порога, срока или текста
предупреждения.

| Что | Где живёт | Кто правит |
| :--- | :--- | :--- |
| Классы техники и алиасы датасетов | `plandb.equipment_class` | Оператор через UI |
| Правила «этап → техника» | `plandb.stage_rule` | Оператор через UI |
| Пороги отклонений D1–D10 | `analysisdb.deviation_rule.params` | Оператор через UI |
| Тексты предупреждений | `data/messages.ru.yaml` | Разработчик |
| Нормативы сроков и выработки | `pos-engine/data/*.json` | Разработчик, со ссылкой на документ |
| Промпты LLM | `report-service/prompts/*.md` | Разработчик |
| Метки стадий и промпты CLIP | `vision-service/data/*.yaml` | Разработчик |

Код содержит **предикаты** — небольшой набор именованных функций-условий
(`no_required_equipment`, `idle_equipment`, `blind_zone`, …), зарегистрированных в реестре.
Строка в `deviation_rule` связывает код отклонения, предикат, параметры и шаблон текста.

## Последствия

**Хорошо:** прямое закрытие критерия оценки, и его можно показать за 30 секунд —
меняем минимум самосвалов в UI, отклонение исчезает. Настройка под конкретную стройку
не требует разработчика.

**Плохо:** ошибка в данных не ловится компилятором. Компенсируется валидацией при
сохранении (класс существует, порог в допустимом диапазоне, шаблон подставляется) и
unit-тестами на каждый предикат.

**Честная граница:** принципиально новое условие — это новая функция-предикат (~30 строк)
и регистрация в реестре. Мы не утверждаем «никогда не нужен код» — мы утверждаем,
что всё, что меняется в эксплуатации, меняется данными.

## Альтернативы

- **Правила в коде.** Быстрее писать, но проваливает критерий оценки и требует
  разработчика для каждой новой стройки.
- **Полноценный DSL или движок правил.** Гибче, но это отдельный продукт со своей
  отладкой; за полторы недели он съел бы методику.
