# ADR-0004. Синхронный REST и очередь задач вместо брокера сообщений

**Статус:** принято, 17.09.2026. Перечень событий уточнён в
[packages/contracts/events.md](../../packages/contracts/events.md) после
[ADR-0012](0012-facts-without-judgement.md): вместо `session.closed` и `session.aggregated` —
`facts.updated`.

## Контекст

В системе есть длинная асинхронная работа (распознавание пакета снимков) и есть связи
между сервисами. Классический ответ — брокер (Kafka/RabbitMQ) и событийная архитектура.
Но у нас полторы недели, один продюсер и один потребитель на каждый поток, и отладка
на демо должна быть мгновенной.

## Решение

- Межсервисное взаимодействие — **синхронный HTTP REST** через изолированные клиенты
  с таймаутами и ретраями для идемпотентных вызовов.
- Длительная работа — **очередь задач `arq` на Redis внутри `site-service`**. Очередь —
  внутренняя деталь одного сервиса, а не шина между сервисами.
- Источник истины по задаче — `image.status` в БД, а не содержимое очереди:
  потеря Redis не теряет данные.
- **Доменные события уже названы** (`packages/contracts/events.md`): `image.registered`,
  `image.analyzed`, `session.closed`, `session.aggregated`, `plan.updated`, `rules.updated`,
  `zones.updated`, `analysis.completed`, `deviation.opened`, `deviation.resolved`.

## Последствия

**Хорошо:** на два контейнера и один язык описания меньше; ошибка видна в трассировке
по `X-Request-Id` целиком; поведение предсказуемо и объяснимо жюри.

**Плохо:** при отказе зависимости вызов падает сразу — компенсируется деградацией
(LLM → шаблон, CV → снимки ждут в `PENDING`). Синхронная связность выше, чем при событиях —
компенсируется тем, что граф вызовов ацикличен и короткий.

**Путь перехода:** замена реализации в `clients/` на публикацию уже названных событий.
Доменная логика не меняется.

## Альтернативы

- **Kafka/RabbitMQ сразу.** Правильно для промышленной эксплуатации, дорого для полутора
  недель, и на демо добавляет класс ошибок «сообщение потерялось, а где — неизвестно».
- **Очередь на самой БД (`SKIP LOCKED`).** Минус контейнер, но плюс собственный код
  планировщика, который придётся отлаживать вместо методики.
