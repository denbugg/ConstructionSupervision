# ADR-0002. Границы сервисов: план / факт / сверка

**Статус:** принято, 17.09.2026. Частично заменено: состав сервисов —
[ADR-0011](0011-generator-and-reports-as-modules.md), распределение выводов и агрегирующие
эндпоинты — [ADR-0012](0012-facts-without-judgement.md).

## Контекст

Нужно разделить предметную область на сервисы так, чтобы границы были объяснимы
заказчику, удобны для параллельной работы и устойчивы к изменениям методики —
а методика будет меняться до последнего дня.

Напрашивались два неверных разреза: по техническим слоям (API / логика / БД — это не
микросервисы, а распределённый монолит) и по экранам интерфейса (границы поедут при
первом же изменении UX).

## Решение

Разрез по **владению данными и источнику истины**:

- **`plan-service` — «как должно быть».** Объекты, справочник работ, календарный график,
  этапы, правила «этап → техника». Данные вводит человек, они редки, требуют истории и аудита.
- **`site-service` — «что видно».** Камеры, зоны, снимки, сессии, детекции, статусы.
  Данные приходят потоком, не правятся вручную, растут линейно от числа камер.
- **`analysis-service` — «совпадает ли».** Не владеет первичными данными: читает план и
  факт по API, производит выводы. Полностью пересчитываем с нуля.

Отдельно вынесены три «знания без данных»: `vision-service` (тяжёлые ML-зависимости),
`pos-engine` (нормативная база Москвы), `report-service` (LLM и рендеринг PDF).

## Последствия

**Хорошо:** методика — главное, за что нас оценивают — целиком в одном сервисе и в чистых
функциях; её можно переписать за час, не трогая ничего другого. Треки команды совпадают
с сервисами. Границы объясняются заказчику одной фразой.

**Плохо:** `analysis-service` делает HTTP-вызовы там, где монолит сделал бы JOIN.
Компенсируется двумя агрегирующими эндпоинтами (план на дату, факт сессии), которые
отдают сразу всё нужное.

## Альтернативы

- **Один `core-service` со всей доменной моделью.** Проще, но методика размывается по
  таблицам, а критерий «архитектура» закрывается слабее.
- **Сервис на экран интерфейса.** Границы зависят от UX, то есть не границы.
- **Отдельный сервис под каждую таблицу.** Оверинжиниринг: десяток сервисов, которые
  всегда деплоятся вместе.
