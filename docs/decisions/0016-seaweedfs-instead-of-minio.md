# ADR-0016. SeaweedFS вместо MinIO

**Статус:** принято, 27.09.2026. Уточняет [ADR-0005](0005-object-storage.md): решение «снимки
и отчёты в S3-хранилище» остаётся, меняется сервер хранилища в стенде.

## Контекст

Стек стоял на образе `quay.io/minio/minio:RELEASE.2024-09-22T00-33-43Z`. С 27.09 он не
скачивается ни с quay.io, ни с Docker Hub: MinIO перестал выпускать готовые сборки
community-версии, репозиторий `minio/minio` переведён в архив, раздаются только исходники.
Стенд жил на локальной копии образа, а на любой другой машине `docker compose pull` падал.
Требование ТЗ — развёртывание одной командой — на чужом компьютере не выполнялось.

Код от MinIO не зависит: оба клиента хранилища (`site-service`, `analysis-service`) вызывают
только базовые операции S3 — проверка и создание бакета, запись, чтение, presigned-ссылка.

## Решение

S3-хранилище стенда — SeaweedFS в режиме `weed mini` (всё в одном контейнере), официальный
образ `chrislusf/seaweedfs` с Docker Hub, лицензия Apache 2.0. Образ закреплён по тегу
и digest: тег читается человеком, digest гарантирует те же байты на любой машине.

- Сервис compose называется `s3`: имя не привязано к продукту, следующая замена не потянет
  переименований. Внутренний адрес — `http://s3:8333`, для браузера — `http://localhost:8333`.
- Ключи задаются переменными `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` из тех же
  `S3_ACCESS_KEY` / `S3_SECRET_KEY`. С ключами SeaweedFS проверяет подпись каждого запроса,
  анонимный доступ закрыт.
- Веб-интерфейс администратора (`:23646`) закрыт теми же ключами — замена консоли MinIO.
- Python-клиент `minio` остаётся: это обычный S3-клиент под Apache 2.0, он работает
  с любым S3 и продолжает выходить на PyPI.

## Последствия

**Хорошо:** стек снова поднимается одной командой на любой машине; сервер хранилища живой
и получает исправления; замена свелась к блоку compose и переменным, код сервисов не менялся
(кроме значений по умолчанию и имени проверки в `/health/ready`).

**Плохо:** адрес хранилища сменился (`minio:9000` → `s3:8333`, `localhost:9000` →
`localhost:8333`), поэтому существующий `.env` нужно поправить по `.env.example`. Данные
старого тома `miniodata` сами не переезжают: их переносят зеркалированием бакетов
(runbook, раздел 2) или заново загружают `make seed`. Консоль SeaweedFS беднее консоли MinIO.

## Рассмотренные альтернативы

- **Собрать MinIO из исходников и выложить образ в ghcr проекта.** Лицензия AGPL это
  позволяет, но мы становимся сопровождающими заброшенного сервера без обновлений
  безопасности.
- **RustFS.** Замена MinIO по API и с похожей консолью, но проект ещё до версии 1.0.
  Для сдачи рискованно.
- **Garage.** Стабилен и лёгок, но при первом запуске нужен отдельный шаг инициализации
  (разметка кластера, импорт ключей) — ещё один контейнер и ещё одна точка отказа.
- **Локальный том вместо S3.** Отвергнут ещё в ADR-0005: нет presigned-ссылок.
