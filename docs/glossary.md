# Словарь предметной области

Единая терминология для кода, API, интерфейса и питча. Если термин есть здесь — в коде
используется именно он, без синонимов.

| Термин | Английский идентификатор | Определение |
| :--- | :--- | :--- |
| **Объект** | `object` | Объект капитального строительства: жилой дом, школа, дорога. Корневая сущность системы |
| **Параметры объекта (ТЭП)** | `tep` | Этажность, площадь, секции, сваи, сменность — вход генератора графика |
| **Справочник работ** | `work_type` | Иерархический классификатор строительных работ (4 уровня) из исходного XLSX заказчика |
| **Этап** | `stage` | Укрупнённая единица работ календарного графика с плановыми датами и ожидаемой техникой. В коде всегда `stage`, слова `milestone` и `schedule_item` не используем |
| **Фаза** | `phase` | Крупный блок графика: подготовительный период, подземная часть, надземная часть, контур и кровля, сети, благоустройство |
| **Генератор графика** | `schedule_generator` | Модуль plan-service: тип и параметры объекта → этапы с датами по МРР, связи, критический путь, правила из шаблона |
| **Шаблон этапов** | `wbs_template` | Для типа объекта: список этапов, доли фаз, связи, зоны и правила «этап → техника» |
| **Правило этапа** | `stage_rule` | Ожидаемая на этапе техника: группы обязательной (`required`), допустимая (`allowed`), сигнатура (`signature`) |
| **Группа обязательной техники** | `required[]` | `{"any_of": [...], "min": N}` — не меньше N единиц любых классов из списка |
| **Сигнатура** | `signature` | Сочетание техники и, при необходимости, стадии по фото, появление которого фиксирует фактический старт этапа |
| **Класс техники** | `equipment_class` | Тип машины в таксономии системы: `excavator`, `dump_truck`, `tower_crane`, … Совпадает с меткой детектора. Единственный источник — `equipment_classes.yaml` |
| **Транзитная техника** | `transient` | Классы, которые приезжают и уезжают рейсами (самосвал, миксер, грузовик). Их присутствие считается за окно из нескольких сессий |
| **Техника, работающая стоя** | `works_in_place` | Классы, которые работают, не сдвигаясь с места (башенный кран, автокран, бетононасос). Неподвижность на рабочем участке с активным этапом для них не простой |
| **Зона** | `zone` | Полигон на кадре конкретной камеры с типом и названием участка |
| **Участок** | `area` | Все зоны объекта с одинаковыми типом и названием. Ключ `ТИП:Название`, например `PIT:Котлован`. Камеры связаны только общей подписью участка |
| **Роль участка** | `zone_type_role` | `WORK` — идут работы, `SERVICE` — машины ждут (въезд, склад), `SAFETY` — опасная зона поверх остальных |
| **Эталонный кадр** | `reference_image` | Снимок камеры, на котором один раз размечаются зоны |
| **Снимок** | `image` | Отдельное изображение с камеры с временем съёмки и идентификатором камеры |
| **Сессия наблюдения (окно)** | `session` | 30 минут по объекту, выровненные по :00 и :30; все снимки всех камер этого окна. Единица, по которой считается состав техники |
| **Рабочая сессия** | — | Окно рабочего дня, целиком лежащее внутри рабочих часов календаря объекта. Выводы строятся только по ним |
| **Факт окна** | `session_fact` | Наблюдение за окно: участок × класс техники × количество, неподвижность, видимость. Без оценок |
| **Детекция** | `detection` | Одна распознанная единица техники: класс, рамка, уверенность, зона, смещение |
| **Точка контакта** | `anchor` | Середина нижней стороны рамки — точка, по которой детекция относится к зоне |
| **Неподвижность** | `static` | Единица не сдвинулась с прошлого окна той же камеры больше чем на `MOVE_THRESHOLD` доли диагонали кадра |
| **Статус техники** | `equipment_state` | Вывод analysis-service: `WORKING` — работает, `IDLE` — простой, `OUT_OF_ZONE` — вне рабочей зоны, `UNKNOWN` — плана на дату нет |
| **Стадия объекта** | `stage_label` | Внешний вид объекта по фото: котлован, сваи, фундамент, каркас, фасад, благоустройство |
| **Визуальная стадия этапа** | `visual_stage` | Как объект должен выглядеть на фото во время этапа |
| **Видимость участка** | `area_visibility` | Сколько камер участка дали пригодный кадр в окне: `OK`, `PARTIAL`, `BLIND` |
| **Слепой участок** | `BLIND` | Участок, не видимый ИИ в окне. По нему выводы не делаются, выдаётся «проверить вручную» |
| **Отклонение** | `deviation` | Зафиксированное несоответствие факта плану: коды D1–D10, с серьёзностью, фактами и снимками-доказательствами |
| **Доказательство** | `evidence` | Снимки и конкретные детекции, на которых основано отклонение |
| **Факты вывода** | `facts` | Все числа, по которым построено отклонение или прогноз; основа объяснимости |
| **Момент расчёта** | `as_of` | На какой момент считается анализ. По умолчанию — конец последней сессии с фактами. Заменяет «сегодня» во всех формулах |
| **Индекс активности** | `activity_index` | Доля рабочих сессий дня, в которых комплект этапа был и работал, 0…1 |
| **Эффективный день** | `effective_day` | Сумма индексов активности; «день, отработанный в полную силу» |
| **Прогресс** | `progress` | Доля выполнения этапа, 0…1; ограничена видимой стадией объекта |
| **SPI** | `spi` | Индекс выполнения графика: фактический прогресс, делённый на плановый на момент `as_of` |
| **Прогноз окончания** | `forecast_end` | Расчётная дата завершения этапа при сохранении текущего темпа |
| **Задержка** | `delay_days` | Разница между прогнозной и плановой датой окончания, в рабочих днях |
| **Уверенность** | `confidence` | Насколько выводу можно доверять: `LOW` / `MEDIUM` / `HIGH`; зависит от объёма данных и видимости участков |
| **Критический путь** | `is_critical` | Цепочка этапов без резерва времени; задержка любой из них сдвигает сдачу объекта |
| **Резерв** | `total_float_days` | На сколько дней этап может сдвинуться, не сдвинув окончание объекта |
| **Версия плана** | `plan_version` | Растёт при любой правке этапов, правил или календаря; фиксируется в прогоне |
| **Прогон анализа** | `analysis_run` | Однократный пересчёт сверки план-факт на момент `as_of` с фиксацией версий входных данных |

## Нормативные документы

| Сокращение | Полное наименование | Что даёт системе |
| :--- | :--- | :--- |
| **МРР-3.2.81** | Рекомендации по определению норм продолжительности строительства объектов Москвы (Москомэкспертиза). Используется **последняя редакция** | Нормативные сроки по типам объектов и фазам; основа генератора графика |
| **СНиП 1.04.03-85\*** | Нормы продолжительности строительства | Федеральная методика для объектов вне таблиц МРР |
| **МДС 12-43.2008** | Методика разработки календарных планов | Разбивка срока на подготовительный период, подземную и надземную части, отделку |
| **СП 48.13330** | Организация строительства | Сетевое планирование, критический путь |
| **299-ПП** | Постановление Правительства Москвы № 299-ПП | Требования к площадке; используются только в рекомендациях по размещению камер |

Подбор машин по КСР, нормы выработки ТСН-2001, окна тишины по закону № 42 и учёт грунта в
АИС ОССиГ в системе не используются: это содержание ПОС, который заказчик назвал ненужным
([ADR-0011](decisions/0011-generator-and-reports-as-modules.md)).
