# py-common — общая инфраструктура Python-сервисов

Маленькая библиотека, чтобы все Python-сервисы выглядели и вели себя одинаково.
**Доменной логики здесь нет и быть не может** — только инфраструктура.

## Состав

| Модуль | Что даёт |
| :--- | :--- |
| `logging.py` | Структурный JSON-логгер в stdout с полями `ts, level, service, request_id, event` |
| `errors.py` | Базовый `DomainError` с полем `code`, единый конверт `{"error": {...}}`, обработчики FastAPI для доменных ошибок, ошибок валидации и непойманных исключений |
| `request_id.py` | Middleware: принять или сгенерировать `X-Request-Id`, положить в контекст, вернуть в ответе и передать во все исходящие вызовы |
| `auth.py` | Зависимость FastAPI, проверяющая `X-API-Key`; единая точка расширения на OIDC |
| `health.py` | Роутер `/health` и `/health/ready` с регистрацией проверок зависимостей |
| `http.py` | Базовый асинхронный HTTP-клиент: таймауты, ретраи только для идемпотентных методов, проброс `X-Request-Id`, перевод чужого конверта ошибок в свои исключения |
| `settings.py` | Базовый класс настроек (общие поля: `env`, `log_level`, `api_key`, `service_name`) |
| `db.py` | Фабрика async-движка и сессии SQLAlchemy, healthcheck БД |
| `pagination.py` | Параметры `limit`/`offset` и модель ответа `{items, total, limit, offset}` |

## Как подключается

Path-зависимость в `pyproject.toml` каждого сервиса. Монорепозиторий — версионирование
не нужно: изменение библиотеки и всех её потребителей происходит в одном коммите.

## Правила

- Никаких упоминаний этапов, отклонений, техники, зон, снимков. Если возникает соблазн —
  место этой логике в `core/` конкретного сервиса.
- Любое добавление сюда оправдано только тогда, когда **уже** есть два потребителя.
  Один потребитель — пусть живёт у себя.
- Обратная совместимость внутри монорепозитория не требуется, но изменение, ломающее
  сервисы, чинит тот же коммит.
